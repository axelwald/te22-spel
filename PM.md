# TE22 spel

Axel Waldenborg 2025-04-14

Arbetets syfte var att skapa ett spel enligt ett visst tema där vi fick samarbeta med estetelever för produktion av assets som vi kunde använda för spelet.
Hela projektet i sig gick lite igenom kreativitetsprocessen av går från en ide till att utföra den, och de svårigheter och lärdomar som man kan ta ur att utöva den processen, det slutgiltiga målet med denna uppgift var att försöka applicera de saker vi lärt oss under våran teknik utbildning samt lära oss nya saker och ta oss över utmaningar som presenterade sig själva under tiden som vi arbetade.

I det här projektet så tycker jag det fanns 3 klara delar, där den första delen handlade om att brainstorma fram ideer i grupp och samarbeta med andra teknikare samt estetare för att lista ut en bra ide som alla verkade gilla och var nöjd med att jobba med.
Den andra delen var själva grund arbetet för spelet, där vi började liksom “wireframa” vårat spel, lista ut den grundmekaniker som vi ville ha utan att lägga in några assets än, och att lista ut hur ville att vårat spel skulle kännas. Under tiden som vi jobbade på det så jobbade estetarna med att tillverka assets för vårat spel, som vi senare skulle använda i sista stadiet av spelets utveckling. Detta handlade om att få en grundide på hur saker skulle se ut när det var klart, och vid denna tid så var det mest kuber där vi programmerade hur den skulle röra sig, kontroller, allt det dära som behövs i grunden.
Den sista delen var implementeringen av allt, implementering av assetsen som estetarna hade gjort, samt de mekaniker som vi i början för att få en förståelse för hur vårat gameplay skulle vara. I detta stadie handlade det om att till exempel ge sprites till vad som var en färgiga kuber, och se till att sprites och animationer fungerade som det skulle.


## Positiva erfarenheter

Jag tyckte att den sista stadiet gick bra, jag hade inga problem med att få assetsen faktiskt fungera med spelet i grunden, och jag tyckte om att försöka klura ut ett bra sätt för att få spelet att fungera på ett objekt orienterat sätt, där jag använder mig av en viss programmerings “paradigm” för att koda spelet på ett organiserat sätt

## Negativa erfarenheter

Jag har inte riktigt så många dåliga erfarenheter för att till störst del vad som gjorde att spelet blev oklart var min motivation att faktiskt jobba på lektionerna, och det är väl det som gick dåligt, att faktiskt jobba på spelet var väldigt sviktande, och att jag borde ta med mig att kanske har lite mer disciplin att få saker klara i tid istället för att skjuta upp det för att eventuellt i framtiden fixa det.




## Sammanfattning

Jag tycker att jag lärde mig mycket även ifall jag inte leverade en klar produkt, jag kände att jag förstog viktigheten med att inte prokrastinera bara för att jag känner för det, och att faktiskt ta i tag saker så att dom inte slinker bort. Det finns många utvecklingsområden som spelet att kunnat varit bättre på, bland dem till exempel health bars, att man faktiskt kan döda fienderna, olika nivåer, mer fiender, mm.
